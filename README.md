# MidnightStudy

기숙사 심야 면학 좌석 신청 웹 앱입니다. Supabase Auth와 PostgreSQL을 사용하며 별도 Node.js 서버가 필요하지 않습니다.

## 기능

- 이름과 비밀번호로 가입·로그인
- 본인의 이름·호실 수정 및 현재 비밀번호 확인 후 비밀번호 변경
- 사감의 8자리 일회용 코드 발급과 비밀번호 재설정 전용 임시 로그인
- 호실에 따른 이용 층 자동 배정 (`A5→5층`, `B5→4층`, `B9→8층`)
- 1·2·4·5층은 7석, 3·6·7·8층은 15석
- 15석 층은 앞쪽 1~7번과 뒤쪽 2×2 좌석 묶음 두 개로 실제 배치 반영
- 신청자 이름과 호실 표시
- 학생당 타임별 한 좌석, 같은 타임·좌석 중복 신청 차단
- 한국 시간 18:00~23:40 신청 및 취소
- 평상시 1타임 23:50~01:00
- 고사 2주 전부터 1타임 23:50~01:30
- 고사 시작 전날 밤부터 종료 전날 밤까지 2타임 01:30~02:30 신청 허용
- 고사기간 2타임은 같은 날 1타임을 신청한 학생만 신청 가능
- 관리자용 고사 일정 설정 화면과 일회용 초대 코드
- 유일한 총관리자의 초대 코드 재발급 및 권한 이전(이전 총관리자는 일반 관리자 유지)
- 총관리자가 일반 관리자 계정을 삭제하는 계정 관리 기능
- 관리자 화면에서 남자 1~4층, 여자 5~8층 좌석을 한 번에 조회
- 관리자가 날짜와 타임을 선택해 과거 신청자·호실·출석 기록 조회
- 학기 시작일 설정 및 시작일부터 학생별 새 호실 입력 의무화
- 관리자의 학생 신청 취소와 23:50~01:00 출석·불참 처리
- 불참 2회 누적 시 한 달 신청 제한, 제한 종료 후 누적 초기화
- 30초 자동 동기화 및 운영 경계 시각 즉시 갱신

## 구성

- `public/`: 정적 웹사이트
- `supabase/migrations/`: 데이터베이스 스키마와 보안 함수
- `public/supabase-config.js`: 브라우저용 Supabase 프로젝트 URL과 publishable key

Publishable key는 브라우저 공개용입니다. 데이터 접근은 RLS와 인증 전용 SQL 함수로 제한됩니다. Secret key나 데이터베이스 비밀번호는 저장소에 넣지 마세요.

## 로컬 실행

```powershell
python -m http.server 3000 -d public
```

브라우저에서 `http://127.0.0.1:3000`을 여세요.

## 정적 호스팅

Cloudflare Pages, Netlify 또는 Vercel에서 저장소를 연결하고 출력 디렉터리를 `public`으로 설정하면 됩니다. 빌드 명령은 필요하지 않습니다.

## 비밀번호 복구 배포

1. Supabase SQL Editor에서 `013_password_recovery.sql`을 적용합니다.
2. Edge Function `password-recovery`에 `supabase/functions/password-recovery/index.ts`를 배포합니다. 이 함수는 로그인 전 호출되므로 `verify_jwt=false`로 배포하며, 자체 일회용 코드/재설정 토큰 검증을 수행합니다.
3. 기본 제공 서버 환경 변수 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`를 사용합니다. 서비스 키를 프런트엔드나 GitHub에 넣지 마세요.
4. 서버 배포 이후 프런트엔드를 배포합니다. 도메인을 바꾸면 함수의 CORS 허용 목록도 수정하세요.

일반 관리자는 학생 코드만, 총관리자는 학생과 일반 관리자 코드를 발급할 수 있습니다. 총관리자 계정 자체의 복구는 이 기능으로 허용하지 않습니다. 반드시 대면 본인 확인 후 코드를 전달하세요.

코드는 시간 제한 없이 1회 사용·오류 5회 제한이며 재발급하면 이전 코드와 임시 로그인이 무효화됩니다. 코드 로그인 후에는 비밀번호 재설정만 가능한 256비트 임시 토큰이 탭의 sessionStorage에 보관되며, 재설정에도 시간 제한은 없습니다. 비밀번호 저장 후 정식 로그인합니다. 실패한 비밀번호 저장 요청도 소비된 토큰을 되살리지 않으므로 새 코드 발급이 필요할 수 있습니다. 기존 비밀번호·권한·신청 기록은 코드 발급만으로 바뀌지 않습니다. 미사용 코드는 자동 만료되지 않으므로 본인에게만 전달하고, 노출되었다면 즉시 재발급하여 무효화하세요.

테스트: `node --test tests/password-recovery.test.mjs` (실제 계정이나 비밀번호를 변경하지 않는 모의 테스트).
